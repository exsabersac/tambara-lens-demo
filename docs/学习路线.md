## 你将走到哪里

```
经典 get/set
    → Profunctor + Strong（Lens）
    → Choice（Prism）与对照表
    → Tambara（统一「上下文强度」）
    → existential / coend ↔ ∀ Tambara
    → 对照真实库，知道下一步读什么
```

全程 **只依赖 base**，逼自己看清类型，而不是调用库 API。

## Step 1 — 经典 Lens（`app/Main.hs`）

**跑：** `stack exec step1-classic-lens`

先把「从结构里取焦点 / 写回焦点」说清楚：

```haskell
data Lens s t a b = Lens { view :: s -> a, set :: s -> b -> t }
```

- `_1` / `_2`：积上的投影（焦点总在）。
- `_cityOf`：嵌套记录上的复合。
- 三条定律：set-view、view-set、set-set。

**直觉：** 合法 Lens 总是能把整树拆成「焦点 × 上下文」，改焦点再装回去。
这一步还没有写出「上下文」类型，但它已经藏在 `set` 的行为里。

---

## Step 2 — Strong 编码（`app-step2/Main.hs`）

**跑：** `stack exec step2-strong-lens`

把同一语义改写成：

```haskell
type Lens s t a b = forall p. Strong p => p a b -> p s t
```

读法：对**任意**带积上强度的 profunctor `p`，都能把「焦点上的 `p a b`」
抬成「整树上的 `p s t`」。

- `lens get setP = dimap (…) . first'`
- `view` 用 `Forget`；`over`/`set` 用 `(->)`。

**关键坑：** 不要 `let l = lens …` 再传给 `view`——rank-2 会被单态化。
直接写 `view (lens …) s`，或一次抽出 get/set。详见原理详解 §6。

**(A) vs (B) 形态对比**（优缺点、例子）：见 [Lens二形态对比.md](Lens二形态对比.md)。

## Step 3 — 对照表（`app-step3/Main.hs`）

**跑：** `stack exec step3-optics-table`

| 约束 | optic |
|------|--------|
| Strong | Lens |
| Choice | Prism |
| Strong+Choice | Affine |
| Traversing | Traversal（占位） |
| 仅 Profunctor | Iso |

Prism 用 `ForgetM` 做 `preview`（可能没有焦点）。
**坑：** `Forget` 对和没有自然的 Choice；别和 `ForgetM` 搞混。

## Step 4 — Tambara（`app-step4/Main.hs`）

**跑：** `stack exec step4-tambara`

一句话：

> `Strong p ≅ Tambara_(,) p`  
> `Choice p ≅ Tambara_Either p`

`introduce :: p a b → p (c ⊗ a) (c ⊗ b)` 就是上下文强度 α。
积张量 → Lens；和张量 → Prism。与 Functor 的 strength 划界见原理详解 §3。

---

## Step 5 — Optic = Tambara 态射（`app-step5/Main.hs`）

**跑：** `stack exec step5-optic-tambara`

三条编码互相 round-trip：

1. 经典 get/set  
2. `∃ c. (s → (c,a)) × ((c,b) → t)`（existential / coend 代表元）  
3. `∀ p. Strong p ⇒ p a b → p s t`

Prism 侧把 `(c,–)` 换成 `Either c –`。这是「optic 是什么」的范畴说法落地。

## 常见坑速览

1. **rank-2 不要单态 `let`**：`let l = lens fst …` 再 `view l` 常卡死。
2. **Forget vs ForgetM**：只读积用 Forget；可能失败的 preview 用 ForgetM。
3. **Strong ≠ Functor strength**：前者是 profunctor 的 Tambara；后者是
   `f a → f (c,a)` 一类（Applicative / monoidal strength）。
4. **Iso 只要 Profunctor**：没有「留下的上下文」，所以不需要 Strong/Choice。
5. **约束越少，optic 越「强」（用途越广）**：Iso ⊆ Lens ⊆ … 在「能当什么用」的方向上。
