## 1. 经典 get/set 为何对应「焦点 × 上下文」

代码：[`app/Main.hs`](../app/Main.hs)

```haskell
data Lens s t a b = Lens
  { view :: s -> a
  , set  :: s -> b -> t
  }
```

### 1.1 积投影是最干净的例子

`_1 :: Lens (a,c) (b,c) a b`：

- `view = fst` —— 焦点是左边；
- `set (_, c) b = (b, c)` —— **右边 `c` 原样保留**。

那个不动的 `c` 就是 **context（上下文）**。合法 Lens 的行为，等价于：

> 总能把整树 `s` 看成「焦点 `a` 和上下文 `c` 的配对」，改焦点得到 `b`，再装回 `t`。

异构（polymorphic）情形：焦点类型从 `a` 变到 `b` 时，整树类型可以从 `s` 变到 `t`（例如 `(Bool, c)` → `(Int, c)`），上下文类型不变。

### 1.2 嵌套记录同理

`Person` 上的 `_cityOf`：上下文是「除 city 以外的整棵人」——姓名、邮编等。`set` 只换城市字段，其余原样。三条定律（set-view / view-set / set-set）正是在说「焦点与上下文拆得干净、装得回去」。

### 1.3 和「随便一对函数」的差别

任意 `s → a` 与 `s → b → t` **不**自动是 Lens。若 `set` 偷偷改了「本该属于上下文」的部分，或 `view` 与 `set` 不一致，定律会失败。光学关心的是：**可合法拆成焦点×上下文的那一类**。

这一观察直接通向第 5 节的 existential 形：`∃c. (s → (c,a)) × ((c,b) → t)`。

## 3. Profunctor optic 的读法与 forall

代码：[`app-step2/Main.hs`](../app-step2/Main.hs)

### 3.1 Profunctor

```haskell
class Profunctor p where
  dimap :: (a' -> a) -> (b -> b') -> p a b -> p a' b'
```

`p a b` 读作「吃 `a` 那边的东西，产出与 `b` 相关的东西」。`dimap pre post`：先把外面的输入预处理成 `a`，跑完再后处理输出。对函数：`dimap f g h = g . h . f`。

### 3.2 读法：`p a b → p s t`

一个 optic 是：**把「焦点上的变换」抬成「整树上的变换」**。

- 你有一个描述「如何改焦点」的 `p a b`（可以是函数 `a→b`，也可以是 `Forget` 的「只读」）；
- optic 给你 `p s t`：同样的「改法」作用在整树上。

### 3.3 为什么要 `forall p. Strong p =>`？

若只对某一个 `p`（比如只对 `(->)`）成立，信息量只相当于一个 `s → t` 的改写器，**不足以**恢复 `view`。  
量化为 **所有** `Strong p`，则：

- 取 `p = (->)` → 得到 `over` / `set`；
- 取 `p = Forget a` → 得到 `view`；

因为「对所有 Strong 都成立」限制极强，恰好相当于「可拆成焦点+上下文」。这就是 van Laarhoven / profunctor encoding 的精髓。

平行的 Functor 编码（van Laarhoven）是 `forall f. Functor f => (a -> f b) -> s -> f t`：换 `f` 抽出运算，组合同样是 `(.)`。原理与 **Lens 组合** 的展开见 [van-Laarhoven教程.md](van-Laarhoven教程.md) §2–§3。

Prism 同理：`forall p. Choice p => …`，用 `ForgetM` 做 `preview`（Step 3）。

构造：

```haskell
lens get setP =
  dimap (\s -> (get s, s)) (\(b, s) -> setP s b) . first'
```

管道：拆出 `(焦点, 整树当上下文)` → `first'` 只改焦点 → `set` 装回。

## 4. Strong/Choice 作为 Tambara；与 Functor strength 划界

代码：[`app-step4/Main.hs`](../app-step4/Main.hs)

### 4.1 上下文强度 α

选定 monoidal tensor（张量）`⊗`：

```text
α :: p a b → p (c ⊗ a) (c ⊗ b)
```

焦点从 `a` 到 `b`，上下文 `c` **平行**带着走。这就是 **Tambara module** 条件（教学里叫 `introduce`）。

| 张量 `⊗` | α（≈） | 经典类 | Optic |
|----------|--------|--------|-------|
| 积 `(,)` | `second'` / `first'` | `Strong` | Lens |
| 和 `Either` | `right'` / `left'` | `Choice` | Prism |

非正式定律（积）：单位 `() ⊗ a ≅ a`；结合；与 `dimap` 相容。和侧单位为 `Void`。

**口号：**

> `Strong p  ≅  Tambara_(,) p`  
> `Choice p  ≅  Tambara_Either p`

### 4.2 与 Functor strength 划界（重要）

| | **Profunctor / Tambara 强度**（本仓库） | **Functor / Applicative strength** |
|--|------------------------------------------|-------------------------------------|
| 典型类型 | `p a b → p (c,a) (c,b)` | `f a → f (c, a)` 或 `(c, f a) → f (c,a)` |
| 作用对象 | **Profunctor**（两参数，左反右正） | **Functor**（一参数） |
| 光学角色 | 定义 Lens/Prism 的「能带上下文」 | 单子/应用函子语义、遍历等另一套故事 |

名字里都有 strength，**不是同一个东西**。看到 `Strong` 类时，想的是 Tambara_(,)，不是 `Data.Functor` 的 strength。

## 5. existential / coend ↔ ∀ Tambara

代码：[`app-step5/Main.hs`](../app-step5/Main.hs)

### 5.1 积上的 Lens

三条等价说法：

```text
(A) 经典     (s → a) × (s → b → t)
(B) ∃c       (s → (c, a)) × ((c, b) → t)     -- existential / coend 代表元
(C) ∀ Tambara_(,)   p a b → p s t            -- 即 forall Strong p => …
```

- **(A)→(B)**：取 `c := s`，`out s = (s, get s)`，`in (s,b) = set s b`（`gsToEx`）。
- **(B)→(A)**：`view = snd ∘ out`；`set s b = in (fst (out s), b)`（`exToGs`）。
- **(B)→(C)**：`dimap out in . first'`（`exToOptic`）。
- **(A)→(C)**：第 2 步的 `lens`（`gsToOptic`）。
- **(C)→(A)**：用 `Forget` 与 `(->)` 取出 get/set（`opticToGs`）。

范畴说法：existential 是 coend `∫^c …` 的代表元；`∀ Tambara` 是其「Tambara 态射 / 自然变换」侧。教学记住 **∃ ↔ ∀** 对拍即可。

Step 5 的 `rtGsEx` / `rtGsOptic` / `rtFull` 对 `_1` 做 round-trip。

### 5.2 和上的 Prism

把 `(c, –)` 换成 `Either c –`：

```text
∃c. (s → Either c a) × (Either c b → t)
  ≅  ∀ p. Choice p => p a b → p s t
```

- `Left c`：匹配失败（上下文 = 改不动的那侧）；
- `Right a`：匹配成功。

经典 `match :: s → Either t a` 与 `build :: b → t` 对应 `c := t` 的代表元（`mbToEx` / `exToPrism`）。`_Just` 演示见 Step 5。

## 6. 常见误区

### 6.1 rank-2：不要单态 `let`

```haskell
-- 易翻车：
let l = lens fst (\(_,c) b -> (b,c))
in view l (True, 1)   -- l 可能被推成某个具体 p0，失去多态

-- 可行：
view (lens fst (\(_,c) b -> (b,c))) (True, 1)

-- 或一次抽出：
let LensGS v s = opticToGs (lens …) in …
```

Step 2 末尾注释强调了这一点。

### 6.2 Forget vs ForgetM

| | `Forget r`（`a → r`） | `ForgetM r`（`a → Maybe r`） |
|--|----------------------|------------------------------|
| 用途 | `view`（Lens，焦点总有） | `preview`（Prism，可能没有） |
| 类 | `Strong` | `Choice` |
| 代码 | Step 2 | Step 3 |

不要给普通 `Forget` 硬上 Choice「失败时返回什么」——没有自然默认值。

### 6.3 Iso 为何只要 Profunctor

Iso 是整树可逆重写：`iso f g = dimap f g`，没有「留下不动的上下文 `c`」，故不需要 Strong/Choice。  
约束更少 ⇒ 值更难造，但用途更广：Iso 可特例化到 Strong 的 `p`，故能当 Lens 用（Step 6 注释）。

### 6.4 Strong ≠ Functor strength

见 §4.2。
